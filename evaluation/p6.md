## 初次验证及修复

初次定向回归的临时目录父目录未创建，导致 71 项 setup error；补建父目录后重跑，原记录保存在本地 outputs/p6/。随后定向回归 68 passed / 4 failed：两项原始 pytest 结果显示 Windows WinError 5 临时文件替换失败，另两项为状态写入期间的 node_exception。四项定向复验 3 passed，剩余一项定位到无消息任务的报告链接问题；已补建空 messages.jsonl。

只读检查增加最终副本缺失检测；一项中间验证因准备运行没有可导出候选而无法删除目标文件，后续在准备检查中显式要求 completed。修复后完整回归 204 项全部通过，五个正式 CLI 案例全部符合预期。中间记录保留在 outputs/p6/；未放宽任何生产门禁、断言或测试计数来得到通过。

## 协作实例与边界

本次两轮任务的 [反馈消息](../examples/contracts/p6/feedback_message.json)、[扩展 Result](../examples/contracts/p6/summary_node_result.json)、[事件](../examples/contracts/p6/events.jsonl) 和 [Event Schema](../examples/contracts/p6/event.schema.json) 可查看。message_sent 的来源轮次为 1，message_consumed 的接收轮次为 2，引用相同候选和 assessment；下一轮 Context 保存这条反馈。

旧 P5 三个真实模型任务均可用新摘要读取，结论与原记录一致，读取前后全部文件摘要/修改时间不变，新增模型请求为 0，见 [兼容性检查](p6_compatibility.json)。当前 Python 3.13.9，`pip check` 无依赖冲突；这不是 P7 干净安装验证。

摘要扩展记录 `business_conclusion_before_export`，当时编排仍为 running；最终完成状态看 state.json。最终报告先保存，再记录 workflow_finished，因此导出摘要的事件序号比最终状态少最后一个完成事件；只读 inspect 从最终状态重建摘要。日志、消息与原子状态不是跨文件事务，磁盘失败不保证新的错误快照可保存，不支持断点续跑。

本次未新增真实模型调用，不作模型质量提升或稳定性结论。可选关系样例及 P0 旧真实基线未补跑。干净目录安装、演示与提交打包属于 P7。

## 复现

```powershell
.\.venv\Scripts\python.exe scripts/p6_acceptance.py
# 只重跑 CLI 案例
.\.venv\Scripts\python.exe scripts/p6_acceptance.py --skip-tests
# 在已有 CLI 索引上单独更新完整 Workflow 回归
.\.venv\Scripts\python.exe scripts/p6_acceptance.py --tests-only
# 单独运行带扩展的两轮反馈任务
.\.venv\Scripts\python.exe -m test_workflow run --demo --with-summary --source examples/validation.py --spec examples/validation.md
```

完整任务位于 outputs/（Git 忽略）；精简索引、JUnit、事件/消息样例和报告文档保留用于交付。运行与排错见 [README](../README.md)、[报告说明](../docs/reporting.md)、[扩展指南](../docs/extensions.md)。
