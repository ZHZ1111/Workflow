## 确定案例

| 案例 | 实测 / 门禁 | 建议 |
|---|---|---|
| calculation 通过 | 3 passed；行覆盖 100%，无分支 null | finish / completed 建议 |
| validation 低覆盖与手动修订 | 首轮 1 passed，60%/50%；第二轮 12 passed，100%/100% | extend_tests → finish，保护 test_score_pass |
| 非法语法 | 未启动 pytest，保留 test_syntax | repair_tests |
| 空测试候选 | 缺少目标导入被拒绝，未启动 pytest | repair_tests |
| 多参数断言错误 | 真实 assertion_failed，证据不足 | request_review / ambiguous_specification |
| 测试未定义名称 | 真实 execution_error / NameError | repair_tests / generation_error |
| 测试导入错误 | 真实 collection_error / ImportError | repair_tests / generation_error |
| 参数化收集错误 | 真实 collection_error，归因不足 | request_review |
| discount 明确边界缺陷 | 保留 100→90 断言及规格表格，真实失败 | request_review / suspected_source_defect |
| 受控无限循环 | 2 秒 timeout，pytest 进程结束 | stop_error / execution_timeout |
| coverage 导出失败 | 本地注入 OSError；真实 3 passed 仍保留，覆盖 unavailable | stop_error / unrecoverable_error |
| 手工底层空测试工作区 | 实际 no_tests，collected=0；单独标 injected | repair_tests，禁止完成 |

生产门禁不允许空候选执行。第十二项直接调用底层工具验证真实 no_tests 分类，再把实测观察交给评估函数；该诊断路径没有放宽执行 Agent 门禁。导出失败注入只作用于 coverage 导出进程，pytest 实际运行。生成客户端离线与 execution observation_mode=real 的含义分别是“没有模型流量”和“真实测试观察”。

低覆盖修订的状态、消息、候选、Context/Result、assessment 均由真实两个节点产生，再由脚本手动调用下一轮；这证明 P2 可以消费 P3 实测反馈，不表示 P4 自动调度完成。最终 task_status 和历史选择尚未由正式编排提交，阶段任务保持 running，结论仅在 assessment 中作为建议。

## 其他验证

错误节点/轮次、缺失或消费过的候选消息、摘要不符、缺失测试文件、源码副本变化、伪造评估/反馈和外部证据目录均被拒绝。有效候选工具调用只一次，重用旧 Context 不会再次执行；超时、不可用覆盖和未知计数不能伪造完成。

执行后源码或测试变化的受控注入保留已取得真实观察，但建议 stop_error。执行证据被破坏时返回 error，不能提交成功 patch，并提供已保存 pytest/JUnit 的任务相对诊断目录。所有此类注入只修改任务副本，原始样例不变。

完整路径从 p3_results.json 的 samples 查询。每轮内层 executions/run-* 保存原工具诊断；外层 evaluations/NN/assessment.json 和 node_results/NN/<node>/ 保存评估与调用证据。当前协议 JSON 和 Schema 已保存在 examples/contracts/p3/。
