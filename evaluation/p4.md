第二轮生成 Context 的 inbox 是首轮执行节点的唯一反馈；候选 ID、来源 round、assessment 摘要、execution、coverage、保护测试均与上一轮一致，并在状态中记为已消费。自动测试还核对实际生成 prompt 包含这条反馈和覆盖提示。最终测试原字节摘要与选中轮次一致，旧轮次未覆盖。

workflow_status=finished 仅说明调度完成，task_status 区分 completed/partial/needs_review/failed。后轮出错时报告分别列出 selected_all_passed=true 和 latest_all_passed=false，保留先前可用测试而不伪称最新候选通过。无可用候选时没有最终测试文件。

## 错误与补充验证

测试验证节点抛错阻止依赖执行、错误只记录固定码、后轮生成失败保留历史、未知动作被拒绝、report 导出失败保存 export_error、中文与空格输出路径可运行、已存在路径不被覆盖、离线入口不读取配置、真实模式配置接线，以及按注册表/定义追加尾部节点。

coverage 导出失败在测试中注入 OSError，真实通过观察仍保留，最终 partial/unrecoverable_error；模型错误使用本地故障客户端验证一次节点调用、三次已知内部尝试计数，未发出实际请求。这些故障测试与真实模型验收明确区分。

早期普通受限测试环境无法解析工作区路径（WinError 5），正式结果使用本机 Python 执行。第一次已有 148 项回归中有 1 项出现 vendor pytest_result.tmp 文件替换 WinError 5（147 passed）；同一 P3 用例随后与 P4 集成定向复验 28 passed，最终全量 175 passed。保留最初失败的本地证据目录 outputs/p4/pytest-regression-1/；未修改 vendor 或为候选增加隐式重跑。
