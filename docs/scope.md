# 需求与范围基线

版本：P0 / 2026-10-09。需求依据为 `TASK_CHECKLIST.md` 中从课程三页说明整理的要求和本次用户选择：开发测试流程，复用 AgentDev，约 60–70 小时。这里冻结基础交付范围；验收状态与完成情况以阶段证据为准。

## 用户场景

用户提交一个 Python 源文件和明确行为规格。系统生成测试、执行测试、分析覆盖和失败、在预算内修订生成测试，输出最终候选、真实执行记录、状态和报告。发现规格支持的源码问题时保留失败断言并请求复核。程序不修改用户源文件。

## 功能需求与验收

| ID | 需求 | 验收方式 | 计划阶段 |
|---|---|---|---|
| FR01 | 接受源码和非空 UTF-8 规格，拒绝不支持输入 | 合法样例通过；非法输入不调用生成 | P1/P4/P5 |
| FR02 | 生成 Agent 独立生成、校验和保存一轮候选 | 注入客户端后获得 `CandidateRound`；无 pytest 调用 | P2 |
| FR03 | 执行 Agent 独立执行、分析、建议动作 | 一次带 coverage 的 pytest，返回结果及依据 | P3 |
| FR04 | 至少两个 Agent 按顺序协作 | 同一任务有生成和执行节点记录，失败阻止依赖节点 | P4/P5 |
| FR05 | 消息与共享状态可校验 | 校验 run_id、轮次、候选标识、接收节点和路径 | P1/P5 |
| FR06 | 依据结果执行有限反馈 | 离线候选完成两轮真实执行，第二轮获得上一轮反馈 | P4/P5 |
| FR07 | 最多三轮；重复、无进展、超时、错误能够停止 | 各停止分支保存明确原因，不超预算 | P4/P5 |
| FR08 | 缺陷和不明确预期保留证据、请求复核 | discount(100) 的预期仍为 90，输出 needs_review | P3/P5 |
| FR09 | 选择历史可用候选并导出 | 后续失败仍保留旧候选；报告标明选中轮次 | P4/P6 |
| FR10 | 可追踪协作及扩展 | 消息、事件、状态、报告可关联；新示例节点可注册 | P1/P6 |
| FR11 | CLI 提供真实与离线模式 | 全流程相同，仅替换客户端；退出码和输出位置明确 | P4 |

验收细化见 [test-plan.md](test-plan.md)。FR01 的输入限制属于沿用的工程边界；三轮、90%/80% 阈值、CLI 和有限反馈是本项目选择，不应描述成课程全部强制条款。

## 输入与业务结论

| 项目 | 约束 |
|---|---|
| 源码 | 单 `.py` 文件，最多 131072 字节，1–5 个顶层同步函数；使用 AST 提取事实 |
| 规格 | 必填非空 UTF-8 文本；预期来源必须能够追溯，域外行为不自行补设 |
| 不支持 | 顶层类、异步语法、多文件工程、第三方依赖、相对/通配符导入 |
| 输出目录 | 每次新建，不覆盖旧任务；候选轮次依次追加 |
| 预算 | 候选总轮数 1–3，默认 3；单次 pytest 超时 1–300 秒，默认 60 |
| 达标 | 真实测试全部通过，目标源码行覆盖 ≥90%，有分支时分支覆盖 ≥80%，场景门禁通过 |
| completed | 达标且无未解决复核问题 |
| partial | 有可用候选但未完整达标，例如预算耗尽或 coverage 不可用 |
| needs_review | 疑似缺陷或规格/责任无法可靠归因，需保留证据 |
| failed | 无可用候选；不能宣称成功 |

无分支时分支百分比为 `null`/不适用，不能编造 100%。编排状态 `pending/running/finished/error` 与测试业务结论分开。

## 质量与交付要求

| ID | 要求 | 证明 |
|---|---|---|
| NFR01 | 可复现安装 | 相对目录安装 vendor 和 Workflow，P7 干净目录验证 |
| NFR02 | 可追溯 | 任一反馈、结论关联源候选、执行记录、规格和轮次 |
| NFR03 | 原输入保持不变 | 执行前后源码哈希一致，工作区内副本异常可留证 |
| NFR04 | 配置脱敏 | Key 只在本地配置；公开状态只含 ModelInfo，不含 AppConfig |
| NFR05 | 扩展代价可控 | 统一节点协议、注册表、流程定义，主循环不增加示例节点特例 |
| NFR06 | 文档匹配实现 | README、Design 和精简验收证据随功能更新 |

基础实现为单进程同步工作流；状态落盘供只读检查，不承诺断点恢复、分布式调度或 exactly-once。执行环境是本机可信代码环境，不承诺恶意代码安全隔离。

## 取舍与评分对应

基础交付：两个 Agent、顺序编排、结构化通信与状态、条件路由、有限反馈、CLI、日志和报告、统一节点扩展接口。可选：基础验收通过后投入最多 6 小时做运行可视化或评估提升。明确不做：拖拽编辑器、远程分布式调度、并行执行、任意仓库测试、自动源码修复、自动安装模型提出的依赖。

流程完整性 40%、Agent 协作 30%、可扩展性 20%、文档 10%，对应 FR01–09、FR04–06/FR10、FR10/NFR05、NFR06。提交文档至少包括 README、Design 和流程图；最终源码包、学号姓名命名、大小与截止日期继续按主清单核对。
